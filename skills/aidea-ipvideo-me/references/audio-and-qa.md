# 音频、合成与验收

## 原声保护

按当次授权与可用服务使用 Rami 或已批准音色；不要把历史无 API key 页面等同永久免费承诺。保留原始 PCM、输入稿、生成参数和哈希，但不将私人音频、账号或凭据提交到公共仓库。新稿先核事实，再生成并确定实际时长。单次生成的原声自然速度优先，禁止为凑固定片长擅自变速。

视觉改版直接复制兼容的 AAC 流（例如 FFmpeg `-c:a copy`）；用一致容器提取方式比较音频哈希，不用整片 MP4 哈希判断音轨。无法直接复制时保存原 PCM 并说明重编码。声音、音量或内容本身获准改动时，不强求哈希一致，记录改动范围。

BGM 按本次音轨做适度频谱避让和柔和 ducking，避免短停顿反复抬升。不要把更响当作更清晰。响度和峰值按具体平台要求判断，没有通用“测量通过即听感通过”。

## 字幕

优先使用真实对齐或可核验时间戳；停顿/字符分配应记录为近似短语时间。检查英语词、专名、孤字尾行、长句异常短时段及声画尾部。图解与口播一致，不因排版改变事实或偷换语义。若不能完整听到声音，不宣称逐字正确或无漏读。

## QA 记录

每项使用 pass / fail / unverified / not_applicable，附依据与最终文件哈希。

1. 编码、尺寸、帧率、时长、流/声道；完整解码，无意外黑尾、缺轨、截断。
2. 实际编码首帧、每种版式、最长字幕、转场前中后、结尾连续帧；末尾不得突然切回正文。
3. 字幕边界/重叠/全文覆盖；相对配音与图解时间是否已实际验证。
4. 角色、帽标、独立品牌文字在实际像素尺寸和手机缩放下可读程度；透明边缘与裁剪。
5. 响度、真峰值、削波；有实际播放条件才标记主观完整试听。
6. 视觉改版的音轨一致性；授权区域外原始帧对比。重编码帧存在微差要另报，不把原始帧零差套用到压缩文件。
7. 平台 UI 安全区与发布清权；未检查就是未验证，不能因为画内不重叠而标记通过。

附带 `media_qa.py` 只覆盖技术子集。它返回测量数据，不会宣告完整视听质量合格。保存失败结果并修正本次涉及的问题；不要借修复重做无关已批准内容。
